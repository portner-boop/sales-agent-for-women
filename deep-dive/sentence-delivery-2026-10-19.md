# Разделение длинных ответов по предложениям

## Требования

Оба примера пользователя содержат несколько предложений в одном длинном сообщении. Разделять такие обычные разговорные ответы при доставке, включая сообщения без вопроса. Не полагаться только на заполнение continuation моделью. Не разрезать предложение по запятой или союзу, не добавлять новые фразы.

## Проект

Новый чистый модуль agent/segmentation.py определяет безопасные границы предложений в тексте от 80 символов. Сокращения, инициалы, числа, цитаты, ссылки и защищённые факты не разрываются. Неоднозначную границу лучше оставить внутри сообщения. Разделение включается только для обычного разговора, исключая follow-up, закрытие, бизнес-переход, подробный ответ и recall.

Компонент принимает проверенный ReplyProposal и возвращает отдельные ReplyProposal для доставки. При разделении восстанавливается исходный текст допустимой опечатки, затем существующий механизм стилизует каждое предложение независимо. При отсутствии разделения существующая опечатка сохраняется. Удаление конечной точки использует штатное правило. Состав и порядок слов не меняются.

question_goal переносится только на предложение с единственным явным вопросительным знаком в исходной части. Если положение вопроса неоднозначно или вопрос без знака, эту часть не делить автоматически: генератор по-прежнему может явно выделить continuation. В остальных предложениях question_goal=null. Генератор сохраняет текущую схему reply/continuation; число доставок определяется количеством безопасно выделенных предложений.

Outbox уже имеет predecessor_id и последовательные задержки. Разрешить цепочку больше двух сообщений того же scope, turn, revisions и deadline; уникальные action_key сохраняют старые ключи первой/второй частей, последующие получают индекс. Неудачная/неизвестная доставка и восстановление процесса должны рекурсивно отменять всех потомков. Новый ввод и stop уже отменяют все ready-части. Счётчик ответов увеличивается только на корне, follow-up и compaction запускаются только после последней доставки. Миграция БД не нужна.

## Последовательность

1. Реализовать чистое разделение и перенос метаданных вопроса/опечаток.
2. Подключить к стилизации доставки, согласовать идентификаторы частей и цепочку outbox, рекурсивную отмену.
3. Проверить оба примера, три предложения, вопросы в разных позициях, отсутствие знака, сокращения/ссылки/цитаты и запреты разделения.
4. Проверить pacing, остановку/новый ввод, отказ/неизвестную доставку, рестарт и однократный follow-up после последней части; выполнить общий регресс и статические проверки.

Рабочий бот не перезапускается; commit/push не выполняются.

## Адаптация flow

По дополнительному требованию пользователя проверяется весь ход, а не только разрезание строки: один счётчик коммерческих ответов на цепочку, регистрация вопроса при доставке его предложения, отдельное ожидание каждой части, восстановление очереди после рестарта, отмена всех потомков при сбое первой или промежуточной части, отмена остатка новым сообщением и /stop. Минутный follow-up и compaction запускаются только после последней части. Старые тесты на единый длинный ответ и ровно две доставки обновлены с сохранением исходных проверок поведения.

## Проверки

Оба пользовательских примера проверены через полный pipeline с одним полем reply: сервер доставляет два сообщения без дополнительной генерации или repair. Проверены цепочки из трёх/четырёх частей, вопрос в первой/последней позиции, сохранение неоднозначного вопроса без знака, защищённые границы и независимое восстановление опечаток каждой части.

69 целевых тестов адаптированного flow прошли. Длинная история на 200 ходах прошла; вариант на 1000 ходов для этой правки не запускался. Ruff, Black, mypy, policy manifest и git diff --check прошли. Первоначальный общий прогон выявил устаревшие ожидания одной/двух доставок и ошибки настройки новых тестов; исправления подтверждены целевым прогоном.

Итоговый общий регресс без long-history: **1015 passed**. Единственное предупреждение — существующий deprecated import Send в trustcall. Рабочий процесс и БД не изменялись; commit/push не выполнялись.
