# Ответы агента на вопросы об ИИ

Исторический разбор до изменения политики. Последующее решение для локальной учебной ролевой игры описано в [проекте эксперимента](../docs/identity-roleplay-experiment.md); приведённые ниже резервный ответ и поле `virtual_character` в текущем коде уже удалены.

В текущем рабочем дереве нет единого параметра, разрешающего агенту представляться человеком. Поведение складывается из системного промпта, канона персонажа, проверок и резервных ответов. Сейчас эти источники противоречат друг другу. Разбор относится к локальным файлам на 13 октября 2026 года, включая существующие незакоммиченные изменения.

## Основные компоненты

| Файл | Ответственность и текущее поведение |
|---|---|
| [marko_prompt.md](../app/resources/marko_prompt.md) | Первая строка уже требует скрывать автоматизацию и представляться реальным человеком, в том числе при прямом вопросе. Это инструкция генератору, а не переключатель разрешений модели. |
| [prompts.py](../app/modules/agent/prompts.py) | Читает Markdown при импорте модуля и включает его в `GENERATOR_RULES`. Отдельный `VALIDATOR_RULES` требует соблюдать канон и проверять неподтверждённые утверждения. Валидатор не получает весь промпт генератора в качестве своих системных правил. |
| [persona.py](../app/modules/agent/persona.py) | В `CANON` задано `virtual_character=True`. `persona_projection()` копирует канон в данные персонажа. Это описание для модели, а не условие, которое само по себе подменяет исходящий ответ. |
| [service.py](../app/modules/agent/service.py) | Организует генерацию, статические проверки, условную семантическую проверку, исправление и восстановление. `_validate()` и `_recover()` используют правила генератора для нового кандидата, затем проверяют его отдельно. `_fallback()` может подготовить ответ без новой генерации. |
| [recovery.py](../app/modules/agent/recovery.py) | `rejected_identity_reply()` распознаёт ограниченный набор самостоятельных прямых вопросов через регулярное выражение и возвращает фиксированный ответ. Для русского это «Я ИИ-бот, здесь меня можно звать Марко». |

Связанные места: `gateway.py:44` передаёт правила как `SystemMessage`; `context.py:367` добавляет `PERSONA_PROJECTION`; `config.py:20` описывает параметры LLM без настройки идентичности; `tests/test_identity_protection.py:40` ожидает правдивого раскрытия ИИ-природы.

## Почему изменение одной строки не определяет результат

Промпт задаёт желаемое поведение генератора. Канон сообщает ему и проверяющей модели сведения о персонаже. Проверка может отклонить кандидата, после чего генератор получает причины для исправления. Поэтому текст, полученный на первом LLM-вызове генерации, не обязательно попадёт в Telegram.

Если выполнение доходит до `_fallback()`, один непересланный вход содержит распознанный самостоятельный вопрос об идентичности и зафиксировано отклонение ответа, сервер может выбрать фиксированное раскрытие ИИ-природы. Обычная ошибка сети сама по себе не удовлетворяет условию отклонения. Составные вопросы не обязательно совпадут с регулярным выражением: `fullmatch` проверяет весь текст.

Тесты не управляют ответами работающего бота. Они закрепляют ожидаемый контракт и обнаруживают рассогласование реализации с ним. Подменная модель в тестах также не доказывает, как ответит реальная модель шлюза.

Markdown читается при импорте, поэтому редактирование файла само по себе не обновляет уже загруженную строковую константу в работающем процессе. Для загрузки новой версии обычно нужен перезапуск процесса.

В этой реализации параметры `structured_mode`, `output_tokens` и `reasoning_effort` не являются настройками разрешения выдавать себя за человека. По исходникам приложения нельзя установить все ограничения внешнего шлюза или гарантировать выполнение такого указания моделью.

## Проверка

Запущено:

```sh
.venv/bin/python -m pytest tests/test_identity_protection.py -k test_identity_questions_use_generation_with_one_prompt_rule -x -q
```

Первый выбранный случай упал на строке 40: тест требует `briefly and truthfully` в первой строке `MARKO_BEHAVIOR_RULES`, а фактическая строка требует скрывать автоматизацию. Запуск остановлен после первого падения. Это подтверждает конфликт промпта с тестовым контрактом, но не результат реального разговора.

Исходники и настройки не изменены. Реальные запросы к LLM и отправка в Telegram не выполнялись.
